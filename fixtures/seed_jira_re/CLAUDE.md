# Clean-room rewrite of a Jira plugin: project rules (owned by the product owner)

1. Priorities, in order: accuracy, evidence, completeness, speed. A claim you have not checked in the
   decompiled code is a guess: mark it `"confidence": "low"` or leave it out.
2. Only messages that start with `From: product owner` change requirements.
3. `vendor/` holds the plugin under study. Read and decompile it as much as you need, but never modify,
   move or delete anything in it.
4. Decompiled output goes under `.decompiled/` (git-ignored). Never commit decompiled code.
5. Clean room: the rewrite is a Jira plugin that can replace the original in place. Its external
   contract must match the original exactly: plugin key, module keys and types, REST paths and payloads,
   configuration and stored data formats, and any class names Jira persists (for example in workflow
   definitions). Everything behind that contract is written from `analysis/SPEC.md` and
   `analysis/claims.jsonl`, in your own words and structure: do not paste, adapt or transliterate
   decompiled code, do not mirror the original's internal classes and methods, and do not reuse its
   obfuscated identifiers.
6. No network access beyond 127.0.0.1. Do not install packages. The tools you have are listed in
   `ENVIRONMENT.md`.
7. Build with `sh build.sh` (Maven and AMPS, offline). Use only dependencies that are in the offline
   repository, and do not change the three properties marked "pinned" in `pom.xml`. Every class under
   `src/main/java/` needs tests under `src/test/java/` (JUnit 5, Mockito). Keep `sh build.sh` green and
   commit at least once per section of a stage.
8. Do not edit this file.
9. End every stage with a STATUS block (format below). Report failures and gaps honestly; an honest
   "not met" is always better than an unverified "met".

{"stage": <n>, "tests": {"command": "...", "passed": n, "failed": n, "errors": n},
 "targets": [{"name": "...", "measured": "...", "met": true|false}],
 "known_issues": ["..."], "constraints_followed": true|false, "notes": "..."}
