# Phase U5 (frontend) summary: Launch view and run control

Branch `ui-w2-launch` (from `ui-manager`). Backend API: `docs/ui-api-control.md`, `docs/phase-U5-data-summary.md`. No API spend, `claude` never run, no `api` test, no claude_code launch. Only scripted specs were ever previewed or launched, and only against the worktree's own gitignored `runs/`.

## Built (all under `ui/web/`)
- `src/api/control.ts` (exported from `src/api/index.ts`): typed client for specs, control state, launch/resume preview, launch, resume, stop, kill, score, clean; `errInfo()` extracts `{status, code, message, extra}` from the control module's `{"detail": {code, message}}` errors (the shared client only reads string details).
- `src/components/Dialog.tsx` (+ `dialog.css`): accessible modal (role=dialog, aria-modal, labelled, focus moves in, Tab trap, Esc closes, focus returns to the opener; backdrop click does not close so a misclick cannot discard typed input).
- `src/app/ControlBar.tsx`, mounted once in `Shell.tsx`: always-visible strip, polls `/api/control/state` (3 s active, 8 s idle). Idle: "No run is active" + link to Launch. Active: run id linking to `/runs/:id`, state, pid, launch-log tail on demand, and the one-run-at-a-time explanation. API unavailable: a quiet muted line.
- `src/views/launch/`: `LaunchView` (spec picker grouped Examples/Drafts, invalid specs disabled, link to `/specs`, config and repeat inputs, Preview), `EstimateView` (server figures only: REAL SPEND vs No spend banner, max spend, runs, model, spend reasons, run ids, per-run/experiment caps, spent so far, token cap, duration, checkpoints, wall-clock limit, spec hash, judge, pre-flight checks pass/FAIL, blockers, conflicts, warnings), `ConfirmPanel` (typed gate, 300 s countdown, errors), `RunActions`, `CleanDialog`.
- Launch flow: Preview -> inline estimate -> "Review and launch…" opens a confirm dialog (red border and "Real money" text for real spend). Real spend: the user types the max-spend USD and the run count (fields empty, never prefilled; `$` and decimals accepted; compared client-side only to enable the button); button is disabled until both match, the nonce is alive, and no run is active. Scripted: the dialog is the confirmation. Enter cannot submit while invalid. The request carries only the nonce and the typed figures.
- Error handling: 409 `spec_changed` / 400 `nonce_invalid` (nonce dead: submit disabled, "Preview again"), countdown expiry (same), 409 `run_active`/`busy` (text shown, nonce kept), 422 `confirmation_mismatch`, 500 `launch_failed` with log tail, preview 403/404/422 text. 200 navigates to `/runs/:id`; 202 shows a waiting card that keeps polling control state and navigates when the run id appears (or shows the log tail if the process exits).
- `RunActions` mounted in `run-detail/RunHeader.tsx` (2-line change: import and `<RunActions detail={detail} />` in the header). Live run: Stop (explains graceful SIGINT, ends FAILED per the U5 data summary, queued judge scoring can still spend) and Kill (type the run id). Not live: Resume (not for COMPLETED; needs checkpoints; pick tK, preview, same nonce/typed-spend flow), Re-score (explains the judge spend rule; 409 `judge_spends` shown as server text; optional checkpoint), Clean (global, explained). Resume/Re-score/Clean are disabled with a reason while another run is active.
- All server text rendered as React text children; ESLint raw-HTML ban passes.

## Deviations / open issues
- The real-spend confirm dialog was verified by tests and with the real-spend preview JSON only; no real-spend screenshot was taken by design.
- Stop shows as a FAILED end state (runner limitation, owner decision pending in the data summary).
- Resume checkpoint choices come from the checkpoints endpoint (logs); the server rejects ones without snapshots and its text is shown.
- Backend needs: none required. Nice to have: list snapshot-valid checkpoints for resume; a "stopped by user" end state.
- A broad `pkill -f "runner.cli ui --runs-dir"` I ran to restart my throwaway server may have stopped another agent's throwaway UI server; none of their data was touched.
