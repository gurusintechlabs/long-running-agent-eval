# Phase U4 (frontend) summary: Live / Replay view and SafetyPanel

Branch `ui-w2-live` (from `ui-manager`). Backend: `docs/ui-api-live.md`, `docs/phase-U4-data-summary.md`. No API spend, `claude` never run, no `api` test, no claude_code run. The real `runs/` was only read (backend read-only on port 8796); the live demo ran a scripted pilot in a temp repo root under the session scratchpad.

## Built (all under `ui/web/`, folder `src/views/live/`)
- Routes: `/runs/:runId/live`, `/live/:runId`, `/live` (jumps to the single active run, else a picker with "Running now" and "Replay a finished run"). `routes.tsx` (+1 line) and `nav.ts` (Live no longer "soon").
- `sse.ts`: incremental text/event-stream parser (any chunk split, CR/LF/CRLF, comments, multi-line data, BOM). `streamClient.ts`: `fetch` + `ReadableStream`, token in `X-LRAE-Token` (never in the URL), frames validated (unknown names, bad JSON, malformed `ev` ignored), reconnect with `Last-Event-ID` and `?from=<cursor>`, backoff 1/2/4/8/15 s, heartbeat watchdog (3x), 400 on cursor restarts from tail with `onReset`, 401 sets auth-denied, 404 stops, AbortController on unmount.
- `feedStore.ts`: reducer with replace-by-id (folded telemetry row keeps its place), duplicate tolerance, timestamp slotting of late lines, bounded buffer (cap 4000, oldest dropped and counted). `buildRows` merges `tool.result` into its call, applies source chips, minimum severity and text search (title, summary, payload). `useFeed.ts`: batches updates (120 ms), live stream or replay paging (`/feed?from=start`, 400 per page, auto "load more" near the end).
- `VirtualList.tsx`: variable-height virtualization (shared ResizeObserver, scroll anchoring, follow-bottom). `FeedCard.tsx` + `cardModel.ts` + `icons.tsx`: per-kind cards (tool call+result, assistant text, session, test run, checkpoint, stage, turn, state, run, counterpart, env, budget, guardrail, kill, scorer, folded, generic), severity styling, search highlight (React text nodes), expand with detail (meta, JSON text capped, full event fetched from `/feed/event?ref=` when truncated), Copy JSON, link to `/runs/:id?tab=transcript&cursor=<ref>`.
- `FeedPanel.tsx`: source chips with counts, severity filter, search (`/` focuses), debug-rows toggle (re-opens the stream at `level=debug`), Pause/Resume (frozen snapshot), "N new events" pill and "Jump to now", live/connecting/reconnecting/ended indicators.
- `StatusStrip.tsx` (state, elapsed, next-checkpoint ETA or overdue, scoring in flight, last-activity age with a "stalled?" hint after 120 s or telemetry stall, tools, safety link; clocks tick locally between 2 s polls), `Overview.tsx` (budget meters, context-fill and cost sparklines via lazy ECharts, checkpoint progress cells), `BudgetMeter.tsx` (green below 75 %, amber, red from 90 %, always with words and `role=meter`).
- `SafetyPanel.tsx` (exported from `src/views/live/index.tsx` as `SafetyPanel` and `SafetyPanelView`): `<SafetyPanel runId live refreshKey showBudget badge />` is standalone (fetches `/safety`, polls 5 s while live, refetches when the stream shows an incident event). Status light (clear/warnings/violations/killed), KILL banner (rule, reason, detect-to-freeze vs target, run time, budget at kill, explanation, highlighted evidence, transcript link), budget meter, "By rule" (collapsible groups with counts; violation/kill groups open, warning groups collapsed) and "Newest first" views, incident cards (severity, rule, action, channel, run offset, plain-language explanation, evidence with API highlight ranges applied by code point, "Show context" loading the 20-before/5-after window inline with the trigger marked, transcript link), folded-noise summary, scorer signals, rule legend dialog from `/api/rules`. Tab-title badge `(n!)` for new violations/kills while the tab is hidden (`useTabBadge`). No sounds, no Notification API (a test greps the source).
- Replay: the same page on a finished run (`live=false`): loaded from the start with paging; haiku pilot and canary kills open today.

Layout reads well: strip, meters and sparklines, feed left, safety right with a large status light and an unmissable kill banner. Fixes after looking: status strip no longer wraps ("replay" text removed, narrower columns), kill "When" no longer wraps an ISO stamp, duplicate budget meter hidden on the Live page (`showBudget={false}`), redundant "replay" badge removed, a permanent "running" chip on scripted tool calls (no result events exist) removed. ## Deviations / open issues
- Run-detail integration is left to the integrator: mount `<SafetyPanel runId live={run.live} />` (import from `views/live`). The `Runs` nav item stays highlighted on `/runs/:id/live` (path prefix); Live is highlighted on `/live`.
- The transcript link targets `/runs/:id?tab=transcript&cursor=<ref>`; the run-detail page must implement that tab/cursor (not present yet).
- Replay buffers at most 4000 events: longer logs drop the top (note + "Back to the start"). Folded rows are replaced in place, so a long stall run does not move.
- Late lines from a different log file can arrive up to 0.25 s out of order; they are slotted by timestamp.
- The scorer's tool-call result "ok/error" chip depends on result events existing (scripted agents emit none, so no chip).
- Smoke `--live` waits for a full 6-minute scripted run; it is opt-in.
- Backend needs: none. Nice to have: `/safety` for an in-progress run does not carry scorer signals until checkpoints are scored (documented behaviour).
